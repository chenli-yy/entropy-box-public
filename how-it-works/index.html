Pipeline

五个环节，三道闸门

闸门是机械的——脚本判定，不通过就 exit 1，产物不进库，不存在"差不多就先放过"。

01编排
主题分批派发，断点可续跑。失败的落账等人工复核，不静默跳过。
○ 无闸门
02规划
种子词 + 领域语义扩展 + Stop Rule，先规划再检索，不搜一次就下结论。
○ 无闸门
03取证
一条技术链一篇文档，文末强制附检索日志：每条 query 登记命中数与用途。
● 闸门 检索量下限
04校验
分链验收 + 结构校验：九节齐全、图环检测、双向一致性、引用闭包。
● 闸门 exit 1
05入库
全局注册表代理键 + 嵌入双视图余弦查重，同一件事全库只有一个条目。
● 闸门 查重裁决
Evidence

"不是编的"，是这么被强制的

Agent 天然会把话说圆。所以我们不靠自觉，靠可数的硬指标：写完文档必须交出检索台账，条数不够就打回重跑。

单篇文档的硬下限

写在 Agent Prompt 里，由脚本机械验收。

WebSearch≥ 10 次
WebFetch≥ 8 次
check_github.py核验仓库存活
fetch_paper.py取论文原文
严禁凭空，未达标不许事后补日志——直接打回重跑。每条检索还要写清用在正文第几节，让结论和来源一一对得上。
