evaluation_metric_definition 分链调研：链 02 导航效率加权度量

范式定位：将二值成功与路径效率（测地线最短距离 / 实际走过的路径长度）相乘，归一化到一个有界 [0,1] 的复合指标 SPL = S × (geodesic / max(geodesic, actual))，配套 SR、SoftSPL、DTG、nDTW 等。这是具身导航基准独有的指标定义范式——把"路径质量"维度编码进成功指标。
状态：✅ 建议保留

1. 真实系统定位

本链对应的真实工程系统是具身导航基准（Habitat PointNav/ObjectNav/ImageNav Challenge）的 SPL 评估流水线。Anderson et al. 2018 提出 SPL 作为导航评估的标准指标，Habitat-Lab 在 habitat/tasks/nav/nav.py 中实现了 Success/SPL/SoftSPL/DistanceToGoal 等 Measure 子类。

1.1 Anderson et al. 2018 "On Evaluation of Embodied Navigation Agents"（SPL 奠基论文）

  • 论文 URL: https://arxiv.org/abs/1807.06757
  • 代码 URL: 无独立代码仓库（论文为方法学建议，Habitat-Lab 实现其指标）
  • 核心贡献: 提出 SPL（Success weighted by Path Length）作为具身导航的标准评估指标，定义了 PointGoal/ObjectGoal/AreaGoal 三类导航任务，建议使用测地距离（非欧氏距离）、连续状态空间、SI 单位、agent 须主动发出 STOP/done 信号
  • 任务分类: PointGoal（坐标指定目标）、ObjectGoal（物体类别指定目标）、AreaGoal（场景区域指定目标）；扩展规格: 图像（ImageGoal）、语言（VLN）
  • 成功判定: agent 须主动调用 'done' 动作表明理解目标已达成；不建议自动终止（"agent 不能仅仅偶然发现目标，它必须理解目标已经达到"）
  • 距离度量: 建议使用测地距离（geodesic distance），考虑环境结构——欧氏距离忽略墙壁障碍，可达性失真
  • 模拟器建议: 连续状态空间（连续移动更接近物理世界部署）、SI 单位、距离阈值 τ 在 1m 内、开源模拟器便于真机迁移

1.3 Habitat Challenge 2023（aihabitat.org/challenge/2023）

  • 官方页面: https://aihabitat.org/challenge/2023/
  • 任务: ObjectNav（找物体类别）+ ImageNav（找图像指定的物体实例）
  • 数据集: HM3D-Semantics v0.2，216 场景，train/val/test = 145/36/35
  • 机器人: HelloRobot Stretch，RGB-D 相机 + 无噪声 GPS+Compass，连续动作空间
  • 评估指标: Success + SPL（引用 Anderson et al. [5]）
  • Success 定义: agent 输出 STOP 命令时，与目标物体任何实例的欧氏距离 < 1.0m，且目标可被 oracle 从停止位置通过转向/俯仰看到（oracle-visibility proxy，"agent 足够近以与物体交互"）
  • SPL 公式（官方页面 LaTeX）:
    $$\text{SPL} = \frac{1}{N} \sum_{i=1}^N S_i \frac{l_i}{\max(p_i, l_i)}$$
    其中 $l_i$ = 起点到目标的测地最短路径长度，$p_i$ = agent 实际走过的路径长度，$S_i$ = 二值成功标志
  • ObjectNav-SPL 特化: 最短路径计算到距 agent 起点最近的目标物体实例（若 agent 靠近 chair1 却停在 chair2，则 100% 成功但 SPL 较低）
  • ImageNav-SPL 特化: 最短路径计算到距 agent 起点最近的图像目标视点
  • 评测规模: 1000 episodes，48 小时时限，AWS EC2 p2.xlarge（Tesla K80 GPU）
  • 注册表已有: AST_BMK_HABITAT_OBJECTNAV、AST_FRM_HABITAT_CHALLENGE、AST_BMK_INSTANCE_IMAGENAV

1.4 Instance ImageNav 任务定义（Krantz et al. 2022）

  • 注册表已有: AST_BMK_INSTANCE_IMAGENAV
  • 论文: Krantz et al. arXiv:2211.15876 "Instance-Specific Image Goal Navigation"

4. 逻辑推演五问

(a) 存在性论证

导航效率加权度量是具身导航基准独有的指标定义范式。它解决的核心问题是：纯成功率（SR）无法区分"走最短路直达目标"与"绕远路最终到达"——两者 SR 相同但效率天差地别。SPL 把路径效率维度编码进成功指标，使导航策略评估同时反映"能不能到"和"走得是否高效"。Anderson et al. 2018 论文引言原文："animals can move nimbly and proficiently through cluttered dynamic environments in pursuit of distant goals"——导航的" proficiency"（熟练度）包含效率维度，纯成功率无法刻画。Habitat Challenge 所有导航任务（PointNav/ObjectNav/ImageNav）均以 SPL 为核心排名指标。

(b) 步骤必要性论证

8 个步骤缺一不可：
- s1_1（episode 初始化）：没有 episode 实例无法开始
- s1_2（目标加载）：没有目标规格无法判定成功
- s1_3（导航执行）：不执行策略无法产生待评估的轨迹
- s1_4（测地最短路径计算）：没有 l_i 无法计算效率比（这是 SPL 区别于 SR 的核心步骤）
- s1_5（STOP 检测与成功判定）：Anderson 2018 强制要求 agent 主动调用 STOP，"agent 不能仅仅偶然发现目标"
- s2_1（实际路径长度计算）：没有 p_i 无法计算效率比
- s2_2（per-episode SPL 计算）：单 episode 的 SPL 是批量聚合的基础
- s2_3（批量聚合）：单 episode SPL 无统计意义，需对 N 个 episode 求均值

(c) 顺序因果论证

顺序严格因果：episode 初始化→目标加载（目标在 episode 中定义）→导航执行（执行产生轨迹）→测地最短路径计算（基于 episode 的 start/goal 计算）→STOP 检测与成功判定（对执行后的最终位姿判定）→实际路径长度计算（对完整轨迹累加）→per-episode SPL 计算（合并 S_i/l_i/p_i）→批量聚合（合并 N 个 episode）。s1_4 与 s1_5 顺序可交换（都依赖 episode 已加载但不互相依赖），但工程上 s1_4 在 s1_3 后立即计算更高效。

(d) 数据流完整性论证

从入口（episode 定义 + 导航策略）到出口（SPL ∈ [0,1]），数据流为：episode→目标规格→动作序列+轨迹→测地距离 l_i + 实际路径 p_i + 成功标志 S_i→per-episode SPL→批量 SPL。无"魔法步骤"——每步输入都来自上一步输出或 Habitat-Sim 外部依赖。关键数据耦合：s1_4 的 l_i 与 s2_1 的 p_i 在 s2_2 合并，s1_5 的 S_i 也在 s2_2 合并，三者缺一不可。

(e) 链间独立性论证

本链指标本体是成功×效率的复合连续指标（含路径质量维度），与其他链的本质区别：
- vs 链01（程序化二值成功）：链01是纯离散二值（episode 级 0/1），不含效率维度；本链在二值成功基础上乘以效率比 l_i/max(p_i,l_i) ∈ (0,1]
- vs 链03（统计严谨性）：链03在 run 分数分布层面做聚合+不确定性量化，不定义单次指标；本链定义单次 episode 的复合指标
- vs 链04（几何精度）：链04是连续几何误差（ADD/IoU），衡量感知模块精度；本链衡量导航任务级成功+路径效率
- vs 链05（人工 rubric）：链05是人工主观评分；本链是仿真器自动计算

5.6 子能力：SoftSPL Computation（软 SPL 计算）

  • 注册表复用: 新建（registry_lookup 未命中 SoftSPL 专门能力）
  • name: SoftSPL Computation
  • name_zh: 软 SPL 计算
  • type: l3
  • description: 对失败 episode 也给部分分的 SPL 变体。SoftSPL 用 (distance_start - distance_current) / max(distance_start, p_i) 替代 S_i × l_i / max(p_i, l_i)，衡量 agent 朝目标取得的进展。输入：start_distance + current_distance + p_i。输出：soft_SPL_i ∈ [0,1]。依赖：DistanceToGoal Measure 的初始与当前值。约束：失败 episode 的 S_i=0 使 SPL_i=0，但 SoftSPL_i > 0（若 agent 取得进展）。性能指标：计算 <1ms。适用场景：RL 训练的密集奖励信号、部分完成度评估。

8. 扩展知识（知识库沉淀）

8.1 SPL 公式的工程含义

SPL = (1/N) Σ S_i × l_i / max(p_i, l_i) 的关键设计：
- l_i / max(p_i, l_i) ∈ (0,1]：当 p_i ≤ l_i 时（agent 走的路比最短路还短，不可能但数值上），比值为 1；当 p_i > l_i 时（绕远路），比值 < 1，惩罚效率低
- S_i × 效率比：失败 episode (S_i=0) 直接 SPL=0，成功 episode 才计算效率分
- max(p_i, l_i) 而非 p_i：防止 p_i < l_i 时比值 > 1（agent 不可能走得比最短路还短，但数值保护）

8.2 SR vs SPL 的区别

  • SR (Success Rate) = (1/N) Σ S_i：只看"能不能到"，不看效率
  • SPL = (1/N) Σ S_i × l_i / max(p_i, l_i)：既看"能不能到"又看"走得是否高效"
  • Habitat Challenge 2023 官方："We measure performance along the same two axes as specified by Anderson et al.: Success (Did the agent navigate to an instance of the goal object?) and SPL (How efficient was the agent's path compared to an optimal path?)"

8.3 SoftSPL 的作用

SoftSPL 对失败 episode 也给部分分，用 (distance_start - distance_current) / max(distance_start, p_i) 衡量进展。作者观点：SoftSPL 对那些"SPL=0 但朝着目标取得进展"的 episode 特别有用（SoftSPL > 0），适合作为 RL 训练的密集奖励信号。

8.4 Anderson 2018 的关键建议（论文原文摘录）

  • 成功信号："we suggest adding a dedicated action to the agent's vocabulary. The action could be called 'done', and indicates that the agent is ready to be evaluated"
  • 测地距离："we recommend using the geodesic distance, that is the shortest path distance in the environment"——欧氏距离忽略墙壁，"the agent might be close to the target object in Euclidean distance, but separated from it by a wall"
  • 连续状态空间："continuous state space better reflects the conditions of the agent's deployment in the physical world"
  • SI 单位与 1m 阈值："we recommend the use of SI units, with distances within 1m"

8.5 其他导航评估指标

  • DTG (Distance To Goal)：agent 停止时距目标的距离，衡量"差多远"
  • nDTW (normalized Dynamic Time Warping) = exp(-DTW(p,q) / (|p| × d_th))：衡量预测路径 p 与参考路径 q 的相似度，[0,1]，越大越好
  • NEES (Normalized Estimated Error Squared)：衡量卡尔曼滤波一致性（非导航专有，但用于导航状态估计评估）
  • CLS (Coverage-weighted Length Score)：覆盖目标的路径长度得分
  • SPL 变体：ObjectNav-SPL（最短路径到最近目标实例）、ImageNav-SPL（最短路径到最近图像视点）

10. 论文知识提取（A 段强制产出）

10.1 Anderson et al. 2018 "On Evaluation of Embodied Navigation Agents"（arXiv:1807.06757）

  • 论文 URL: https://arxiv.org/abs/1807.06757
  • 代码 URL: 无独立代码仓库（方法学建议，Habitat-Lab 实现其指标）
  • 正文阅读来源: CSDN 论文笔记 https://blog.csdn.net/weixin_45800242/article/details/131791889 + Habitat Challenge 2023 官方页面 https://aihabitat.org/challenge/2023/（含 SPL 公式 LaTeX）

问题与动机

具身导航研究在 2016-2018 年爆发式增长，产生了大量"有时不兼容的任务定义和评估协议"（论文原文）。不同论文用不同指标、不同模拟器、不同任务定义，导致方法间无法公平比较。论文召集工作组研究导航研究的实证方法，"to coordinate the ongoing and future research in this area"。

核心洞察

  1. 成功须主动声明：agent 不能偶然到达目标，必须理解目标已达成。论文原文："an agent cannot simply stumble upon the goal, it must understand that the goal has been achieved. To indicate this understanding, we suggest adding a dedicated action to the agent's vocabulary. The action could be called 'done'"
  2. 测地距离优于欧氏距离：欧氏距离忽略环境结构，"the agent might be close to the target object in Euclidean distance, but separated from it by a wall, and so is actually far away in terms of reachability"
  3. SPL 同时衡量成功与效率：纯成功率无法区分"直达"与"绕远路"，SPL = S × l/max(p,l) 把效率维度编码进成功指标

方法（含关键公式）

SPL 核心公式（Habitat Challenge 2023 官方页面 LaTeX 摘录）：
$$\text{SPL} = \frac{1}{N} \sum_{i=1}^N S_i \frac{l_i}{\max(p_i, l_i)}$$
其中：
- $l_i$ = length of shortest path between goal and target for an episode（测地最短路径长度）
- $p_i$ = length of path taken by agent in an episode（agent 实际路径长度）
- $S_i$ = binary indicator of success in episode $i$

任务分类：PointGoal（坐标）、ObjectGoal（物体类别）、AreaGoal（场景区域）；扩展规格：图像（ImageGoal）、语言（VLN）。

模拟器建议：连续状态空间、SI 单位、距离阈值 τ 在 1m 内、开源模拟器。

关键实验/ablation 结论

论文为方法学建议（非实验论文），但提供了基准场景：
- SunCG：500 单层房屋，2,737 房间，110,000 m²，41,158 物体；agent 体宽 0.2m，成功阈值 τ = 0.4m（体宽两倍）
- Matterport3D：真实扫描 3D 重建
- AI2-THOR：ObjectGoal 设定，物体 1m 内且在视场内为"可见"
- Gibson：572 建筑，1,447 层，211,000 m²

局限与适用边界

  • SPL 假设有 ground-truth 位姿与 NavMesh（真机无 ground-truth 不可用）
  • 测地距离计算依赖 NavMesh 质量（NavMesh 不准则 l_i 不准）
  • 1m 阈值是经验值，不同任务可能需调整
  • 论文未提供代码实现（由 Habitat-Lab 等后续实现）

与链中其他论文的关系

Anderson 2018 是 SPL 指标的奠基性定义，Habitat-Lab（Savva et al. ICCV 2019）实现了其指标，Habitat Challenge 2023 将其标准化为竞赛评测协议。本链的所有工程实现都源自这篇论文的方法学建议。

10.2 Habitat 1.0（Savva et al. ICCV 2019）

  • 论文 URL: https://arxiv.org/abs/1904.01201
  • 代码 URL: https://github.com/facebookresearch/habitat-lab

问题与动机

具身 AI 研究缺乏高效、可复现的仿真平台——现有平台要么渲染慢，要么不支持大规模训练。Habitat 旨在提供"high-performance 3D simulation platform for embodied AI research"。

核心洞察

  1. 模块化设计：Habitat-Sim（C++/Python 渲染）+ Habitat-Lab（任务/算法）解耦，可独立替换
  2. 高性能：多进程并行仿真，数千 FPS 渲染，支持大规模 RL 训练

方法

Habitat-Sim 提供 NavMesh + geodesic_distance + shortest_path 等导航基础设施。Habitat-Lab 提供 Measure 基类与 Success/SPL/SoftSPL/DistanceToGoal 子类。

关键实验结论

Habitat 1.0 支持 PointNav 训练，DD-PPO 在 64 GPU 上训练 64M steps 达到 SOTA。

局限与适用边界

  • 仅支持室内场景（不支持户外）
  • 依赖 3D 重建数据集（Matterport3D/Gibson/HM3D）

与链中其他论文的关系

Habitat 1.0 是 Anderson 2018 SPL 指标的工程实现载体，Habitat 2.0/3.0 扩展到重排与人机交互但导航评估指标沿用 SPL。
